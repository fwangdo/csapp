# 9. Virtual memory

- Q. 가상 메모리는 왜 필요한가? A. 다양한 프로세스마다 고유의 메모리가 필요하다면 너무나 큰 메모리가 필요하고, 쉽게 corrupted 되기 때문.
- 가상 메모리가 주는 세 개의 능력(capabilities).
  - 1. 메인 메모리를 디스크에 대한 일종의 캐시로 사용하도록 하는 역할을 하고,
  - 1. 단일한 규칙의 메모리 주소를 여러 프로스세스에 공급하여 메모리 관리를 쉽게하며,
  - 1. 다른 프로세스에 의해 특정 프로세스의 메모리가 오염되는 것을 막음.

## 9.1. 물리 / 가상 주소

- 물리 주소(physicall adressing): M개의 바이트조각이 연속적으로 나열된 형태.
  - load 명령을 받으면? 메인 메모리에서 요구된 위치에서 그만큼의 메모리를 받아 cpu에게 돌려줌.
- 가상 주소(virtual addressing)
  - cpu가 메인메모리에 접근할 때 가상주소를 생성여 접근함. 보내지기 전에 물리 주소로 변경되고 이걸 주소번역(address translation)이라고 함.
  - cpu에는 memory management unit(MMU)라는 게 존재하고 이게 가상주소를 번역해줌. 번역 정보는 메모리 안에 page table 형태로 존재하고 os가 이걸 관리함.
  - 번역방향은 virtual to physical임.

## 9.2 주소 공간

- n비트 공간이 있으면 주소 공간은 당연히 [0, 2^-1] 같은 꼴을 생각할 수 있음.
- 여기서 메모리 주소가 몇 비트로 표현되느냐에 따라 특징지어줄 수 있음(e.g., 32-bit, 64-bit..)
- 중요한 특징은, 저장되는 값인 data bytes와 그 속성인 주소를 구분할 필요가 있다는 것임.
  - 하나의 데이터에 대해 두개의 주소를 가질 수 있음. 그래서 물리 주소, 가상 주소가 동시에 하나의 데이터를 가리킬 수 있는 것.

## 9.3 캐싱관점에서의 VM

- 가상 메모리(VM)은 N 바이트가 연속되는 배열이라고 볼 수 있고, 해당 주소가 virtual address임. 즉, virtual address -> data 매핑이 성립한다.
  - 단, 정말 데이터가 저장되는 것은 아니고, "논리적으로는 매핑이 가능하다"임. 실제 물리적으로 저장되는 곳은 다른 곳이다.
- 이 주소의 "컨텐츠"들은 메인 메모리에 캐싱된다. 이때 더 아래 계층(e.g., disk)는 블록으로 쪼개지고 이 중 일부를 윗계층(e.g., 메모리)으로 전송하기 위한 전송유닛으로 사용한다.
  - 이런 형태의 쪼개진 블락을 VM은 virtual page라고 칭하고, 피지컬 메모리 계층에서는 physical page라고 칭함.
  - 따라서 vp와 pp는 "메모리 공간"에 대한 매핑으로 볼 수 있음.
- 가상 페이지들은 세 가지 상태로 구분할 수 있다.
  - unallocated: vm에 의해 할당되지 않은 영역. 아무런 데이터도 없음.
  - cached: 현재 피지컬 메모리에 할당된 영역
  - uncached: 현재 피지컬 메모리에 할당되지 않은 영역.
  - Q. 가상 페이지와 피지멀 페이지가 서로 대응관계에 있는데, 가상에는 있으나 피지컬에는 없다는 게(uncached) 무슨 말인가?
  - A. VM상에서 페이지가 할당되었는데, pp에 데이터가 없는 경우임. 예를 들어 VP에 데이터가 있었고 PP에서 캐시했는데 PP가 evicted되면 이런 상태일 것.
  - Q. VP가 PP를 캐싱하는 게 아니고, PP가 VP를 캐싱하는 게 맞나? 방향이 반대 아닌가?
  - A. 반대 아니다. PP가 VP를 캐싱한다. VP가 논리적 기준이 되는 페이지고, PP 일종의 캐시 슬랏이다.
- 정리하자면,
  - VP <-> PP는 메모리 공간에 대한 매핑이다.
  - VM이 VP를 할당하고, 이에 따라 VP / PP 간에 세 가지 상태가 존재할 수 있다. 이 셋을 가르는 핵심 키워드는 할당되었는가 & 데이터가 존재하는가 이다.

### 9.3.1 DRAM cache organization

- 지금까지 언급한 virtual page가 있는 캐시를 DRAM-cache라고 부르고, SRAM용 캐시는 SRAM-cache로 부른다.
- 캐시미스가 날 때, SRAM보단 DRAM에서 일어나는 게 더 타격이 크다. DRAM에서 가져오는 것보단 disk에서 가져오는 게 훨씬 느리기 때문.
- 따라서 DRAM에서는 최대한 캐시 미스를 피해야하고 이런 이유로 임의의 PP를 VP가 사용할 수 있도록 하는 구조를 만듦. 이걸 fully associative하다고 함.
  - Q. VP의 특성인 페이지 단위 관리를 고려해보면 당연한 것 같은데 왜 대단한 것처럼 말하나?
    - A. 캐시를 생각해보면 다름. 캐시는 일종의 해시라서 공간이 더 남아있더라도 해시값이 다르면 저장 못할 수도 있음. 사실상 캐시와 메모리간 매핑이 있는 것.
    - 반면 가상 페이지는 완전히 논리적으로 운영되기에 그런 문제로부터 자유로움.

### 동작과정

- 가상 <-> 물리 매핑은 os를 통해 이루어지며, 하드웨어상에서는 mmu라고 하는 부품을 통해 수행된다.
- 또한 os 안에서 가상 메모리 -> 물리 메모리 매핑이 있고 이걸 page table라고 한다.
- page table entries를 보자. set / address field로 나누어져있고, set이 1이면 해당 가상 메모리 주소에 대응되는 PP가 DRAM에 올라왔다는 뜻.
  - 반대로 0이면 현재 캐싱되지 않았다는 뜻. 이때는 address field가 null일 수도 있고, disk를 가리킬 수도 있음.
  - Q. 물리주소는 아는데 가상주소는 어떻게 아는가? A. 인덱스 값이 VP의 주소라고 생각하면 된다. PTE[1]이면 1번 VP에 대한 정보라는 식.

### 정리해보자면

- VP는 일종의 "논리적 정체성(identity)"이다. 프로세스 입장에서는 "여기에 데이터가 있다"고 생각하고 접근한다.
- 그렇다면 그 주소에 정말 데이터가 있는가? 그렇지 않다. 다른 물리 메모리에 존재한다.
- 그럼 어떻게 찾아가는가? MME를 사용해서 PTE로 간다. 거기서 valid bit이 1이면 DRAM 안에 있는 거고, 그렇지 않으면 uncached거나, 아니면 valid하지 않거나.
- 즉 VP는 가상으로 별도의, 구분되는 메모리 영역을 만든 것이고, 거기서 "내가 관심이 있는 메모리가 어느 영역에 있든 추상화해서 사용할거다"는 생각으로 만들어진 거다. "실제 데이터가 어디에 있고 어떤 상태인가?"는 PTE를 통해서 관리된다.
