# cp 7. linker

## c 컴파일 과정?

- 전처리기 -> 컴파일 -> 어셈블러 변환 -> 링킹

## 정적 링킹

- 리눅스의 `ld`는 relocated file(.o)와 다양한 인자들을 입력으로 받아 실행파일(exe)을 내놓는다.
  - 이 실행파일은 쉘에 입력하면 운영체제의 loader가 메모리에 올리고 실행해줌.
- ld와 같은 링커는 크게 두 가지 역할을 한다.
  - symbol resolution: 전역변수, 함수이름, static variable 등, 사용사례와 실제 정의를 짝지어줌.
  - relocation: 컴파일러 / 링커는 통상 주소를 0번부터 시작하는데, 함수 / 변수가 사용될 경우, 실제 저장되어 있는 주소를 가리키도록 해줌.

### relocated object file의 구조

- 맨 위에 elf header가 있고, 16 바이트 구성. 해당 파일에 대한 간단한 정보를 담고 있음
  - 예: 파일 타입, 테이블 크기, 머신 타입 등.
- text: 컴파일된 코드
- rodata: read-only data. printf의 format string등이 해당.
- data: global / static 변수들이 정의되는 곳. 로컬 변수들은 런타임에 다른 곳에서 다루어짐.
- bss: "초기화되지 않은 global / static 변수"들이 저장되는 곳. 일종의 placeholder.
- symtab: symbolic table. 함수나 전역변수가 정의 / 참조되는 곳을 기록.
- rel.text: text에서 외부에 의해 주소가 변경될 수도 있는 영역을 기록(e.g., external call, global variable state change.)
- debug: 디버그 심볼
- line: 라인 넘버 매핑
- strtab: 코드에 대응되는 문자열 매핑

### 링커가 구분하는 심볼의 세 종류

- 여기서 모듈은 "한 파일", 글로벌 변수는 "밖에사도 볼 수 있는 변수(e.g., static이 아닌 변수)", 로컬 변수는 "밖에서는 볼 수 없는 변수(static)"을 의미.
  - pl에서 통상 정의되는 컨셉(함수 밖 / 안)과는 다소 다름. 링커 관점에서의 심볼 정의임. 밖에서 보는가 안 보는가가 중요한 문제.
- 종류1: 모듈 내에서 정의된 글로벌 변수
- 종류2: 모듈 밖에서 정의된 변수(extern)
- 종류3: 모듈 내에서 정의된 "로컬 변수"

### 심볼과 섹션

- 심볼에 대한 정보는 섹션에 저장되고 보통 이 섹션은 세 가지로 구분된다.
- ABS: relocated가 되어서는 안 되는 심볼들을 저장.
- UNDEF: 참조는 되지만 해당 모듈에서 정의되지 않은 심볼들
- COMMON: 아직 할당되지 않고 초기화 되지 않은 심볼들을 의미.

### 정적 라이브러리 동작 방식

- 링커가 archive 파일인 .a를 입력으로 받는 경우를 가정한다. 이때 오브젝트 파일을 E, 정의되지 않은 심볼을 U, 정의된 심볼을 D라고 한다.
- 아카이브 파일을 순회한다. 순회 iteator를 m이라고 할 때, m이 U와 매칭되는 경우 U와 D를 업데이트하고 m을 E에 추가한다.
- 모든 순회가 끝났음에도 U가 남아있을 경우 에러를 발생시킴
