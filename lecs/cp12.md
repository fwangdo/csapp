# 12. Concurrent Programming

## 12.1 프로세스와 동시성 프로그래밍

- 동시 동작하는 프로그램을 만드는 가장 쉬운 방법? fork, exec, waitpid 사용하기.
- 예를 들어 두 개의 클라이언트가 있고 하나의 서버가 있는 상황을 생각해보자.
  - 서버는 listening discriptor를 열어두고, 요청이 오길 기다린다. 연결이 성립하면 connected descriptor로 연결한다.
  - 그리고 서버는 fork로 child 프로세스를 만든다. 정확히 동일한 형태의 descriptor table이 만들어진다.

### 프로세스에 기반한 동시성 서버

- sigchld 핸들러가 반드시 존재해야함. 이유? 서버는 오래 동작하기 마련이라 child process가 reap되지 않으면 자원낭비가 심할 것이기 때문.
- 부모 / 자식 프로세스가 있을 때 connfd는 "각각" 닫아야한다. 부모걸 닫는다고 해서(혹은 그 반대도!) 자식 것도 닫히는 게 아니다.
- file table entry는 ref count가 있다는 걸 항상 명심해야. 부모 / 자식이 둘 다 connfd를 닫지 않으면 메모리 누수가 지속 발생할 수 있음.

### 프로세스 기반 서버의 장단점

- 장점은 깔끔하다. 프로세스는 각각의 가상 메모리 공간을 가지기 때문에 덮어쓰기(overwrite) 문제가 발생할 가능성이 없음.
- 단점은 데이터 공유가 어렵다는 것. IPC라는 프로세스간 데이터 전달 방법이 필요한데 오버헤드가 만만치 않음.

## 12.2 동시 프로그래밍 with I/O multiplexing

- 에코 서버를 만든다고 가정해보자. 크게 고려해야할 두가지 io event가 있다.
  - 첫 번째는 유저로부터 연결 요청을 받아들이는 것이고,
  - 두 번재는 서버에 달린 키보드로부터 standard input으로 들어오는 바이트를 read로 읽는 것이다.
  - 문제는 둘 중 어느 쪽에도 우선순위를 주기가 어렵다는 것. 이럴 때 등장하는 게 i/o multiplexing이라는 것이다.
- 방법론은 기본적으로 `select` 함수를 이용한다. select는 커널에게 앞으로 일어날 하나 이상의 io event를 위해 현재 프로세스를 잠시 지연지킬 수 있는지를 요청하는 용도로 사용한다.

### usage of select

- select는 `int select(int n, fd_set *fdset, NULL, NULL, NULL)`와 같이 생김.
  - fd_set은 비트벡터 형태이고, 대응되는 디스크립터가 1이면 fdset에 포함되었다고 판단할 수 있음.
  - 디스크립터 셋에 대해서는 크게 세가지 행동 가능. 1. allocate, 2. 다른 변수에 해당 타입을 가진 것을 대입할 수 있음(일종의 복사로 추측됨) 3. FD_ZERO, FD_SET, FD_CLR, and FD_
ISSET 사용.
- select는 fd_set 인자가 ready_set을 지칭하도록 side-effect를 만들어낸다.
  - 그럼 여기서 ready라는 게 정확히 뭔가? ready는 읽어야할 바이트가 존재할 때, 막던 block이 사라져 read할 수 있을 때가 되는 경우를 ready라고 이야기한다.

### A Concurrent Event-Driven Server Based on I/O Multiplexing

- io multiplexing은 concurrent event-driven 프로그램의 기초로 사용될 수 있음.
  - 하나 참고해두어야 할 것은 "concurrent"와 "parallel"은 다른 개념이라는 것. 병렬실행되지 않아도, A라는 일이 종료되지 않은 채 B가 실행되면 "동시성"이라고 생각할 수 있음.
  - logical control flow에서 context swtiching을 하는 것을 고려할 것. cpu가 하나여도 동시성은 가능하다.
- 이 관점에서 보면 state machine이라는 게, state, input events, transition으로 볼 수 있고 self-loop을 돌며 계속 상태를 전이시키는 것이라고 생각할 수 있다.
  - 이 관점에서 새로운 클라이언트 k가 들어오는 걸 생각해보자. 새로운 state machine s_k를 만들고, 디스크립터 d_k를 만들고.. k에 대응되는 개념을 생각하는 방식으로.
- io 멀티플렉싱은 결국 self-loop 안에서 들어오는 요청을 시퀀셜하게 처리하는 모델로 생각할 수 있는 듯하다.

### i/o multiplexing의 장단점

- 장점은 프로그래머가 이벤트를 더 쉽게 다룰 수 있게 된다는 것. 또한 프로세스 기반으로 관리되지 않기에 context switching 비용도 적다.
- 단점은 구현이 어렵다는 것. 특히 이벤트의 단위를 더 잘게 쪼갤수록 구현이 더 어려워진다. 또한 single process이므로 멀티코어를 제대로 사용하기 어렵다.

## 12.3 동시성 프로그래밍 with threads

- thread부터 다시 정의해보자. thread는 하나의 프로세스 맥락(context)에서 실행되는 logical flow들이다.
  - 각 thread는 thread context라는 걸 가진다. thread id, stack, stack pointer, program counter, condition codes, general purpose register 등이 해당.
- 스레드 모델은 하나의 프로세스에서 돌아가지만 여러개의 스레드를 통해 실행하는 방식이다.

### 스레드 실행 모델

- 스레드의 첫 시작은 메인스레드라고 부른다. 여기서 스레드를 하나 만들면 peer thread가 되고 thread pool에 들어가게 된다.
  - 스레드의 재밌는 점은 위계가 없다는 것. 모두 동일한 pool에 들어가고 부모-자녀 구분 없이 누구나 동일 pool에 있는 스레드를 kill할 수 있다.
- 스레드도 당연히 context switching이 필요하다. 단, 프로세스의 스위칭 비용보다는 싸다(당연하다, 훨씬 context가 적으니까)
- read, sleep 혹은 interval timer에 의해 context switching 타이밍이 정해진다.

### posix 스레드

- c에서 스레드를 조작하기 위한 표준 인터페이스임. pthreads라고 부르기도 함.
- 세 가지 종류의 메서드를 알아보자. pthread_exit, pthread_cancel, pthread_join.
  - pthread_exit: 자기 자신(스레드)을 종료. peer thread도 다 죽는다.
  - pthread_cancel: 특정 peer thread에게 종료를 요청함. 해당 thread는 cancellation point에서 종료한다.
  - pthread_join: 특정 스레드가 종료할 때까지 기다리고 return 값으로 thread routine이 thread_return으로 지정해둔 주소를 받는다.
- pthread_detach는 좀 다르다. join은 peer thread가 명시적으로 reap을 한다면 detach는 미리 실행해둘 경우, 끝나는 순간 알아서 자원이 회수된다.
- 즉 클라이언트로부터 리스닝 같은 작업을 수행해야하는 경우 detach를 해두면 효과적일 수 있다. 어차피 일회성 작업이고, 알아서 죽도록 만들면 leak을 방지할 수 있음.

## 12.4 스레드된(threaded) 프로그램에서의 공유변수

### 12.4.1 스레드 메모리 모델

- 다른 스레드끼리 레지스터 값을 공유할 수는 없다. 그러나 virtual memory 값들은 공유할 수 있다.
  - 레지스터 값을 공유한다는 게 뭐냐? 말 그대로 "논리적 레지스터" 값이고, context switching 같은 걸 할 때 저장되는 레지스터 값들은 포함되지 않은 것임을 의미.

### 12.4.2 변수를 메모리에 매핑하기

- 전역 변수: 함수 바깥에서 선언되는 변수. 가상 메모리의 read / write 영역에 저장된다. 단 하나의 인스턴스만 가상 메모리에 저장되며 모든 스레드가 접근할 수 있다.
- 로컬 자동 변수: 함수 안에서 선언되는 일반적인 변수. 여기서는 static이 없는 경우라고 정의. 스레드 스택마다 그 스레드 각각의 변수로 가지도록 설정.
- 로컬 정적(static) 변수: 함수 안에서 static으로 사용되는 변수임. 전역변수와 매우 유사함. 가상 메모리 read / write 영역에 저장되며 프로그램 실행 중 단 한 번만 초기화 됨.

### 12.4.3 공유되는 변수들

- 두개 이상의 스레드에 의해 사용되는 모든 변수는 공유 변수로 볼 수 있다.
- 로컬 자동(automatic) 변수라고 해서 공유 불가능한 건 아니다. 동일 가상메모리를 사용하는만큼(=하나의 프로세스에 있는만큼) 주소를 알면 공유할 수 있다. 물론 관리는 별도의 문제지만.

## 12.5 세마포어와 함께 스레드 동기화하기

### progress graph

- 프로세스 그래프란 n개 스레드의 실행을 n차원 공간에서의 궤적(trajectory)으로 표현한 것이다.
- 각 축(axis)은 한 스레드의 진전상황(progres)을 의미한다. 2차원 공간에서는 각각 오른쪽과 위로만 움직이고(backward 불가), 위치는 현재 상태, 궤적은 진행 순서를 의미한다.
- critical section이란? 하나의 논리적 작업 단위로서 다른 스레드에 의해 공유변수가 읽히거나 수정되서는 안 되는 연속동작을 의미한다.
- mutual exclusion(상호 배제)란? critical section이 수행될 때 다른 스레드가 해당 critical section에 진입하지 못하도록 하는 성질.
- progress graph 상에서 궤적을 그려보면 unsafe와 safe 구역이 명확히 나뉘어보인다.

### semaphores

- 먼저 동기화릉 명확히 정의하고가자. 동기화란 실행흐름에서 순서 혹은 제약조건을 명확히 하여 프로그램이 요구하는 올바른 동작을 보장하는 방식.
- 세마포어(semaphore): 다익스트라가 정의한 개념으로, 다양한 실행흐름을 동기화시키기 위한 방법이다.
  - 특별한 타입의 전역 변수로 소개 되며, non-negative 값을 가짐. P와 V라는 특수한 종류의 operation을 지원한다. 해당 변수를 s라고 할 때,
  - P(s): 만약 s가 0이 아니면, 바로 1을 빼고 리턴. 0이라면 해당 스레드를 suspend한다. 해당스레드는 V에 의해 재시작 되며 재시작 될 때 P가 다시 1을 빼고, control을 caller에게 넘긴다.
    - Q1. suspend되면 바로 V가 시작되는가? A. 아니다 별도로 호출해야함.
    - Q2. control을 caller에 준다는 의미가 뭔가? V를 호출한 쪽에서 실행권을 넘긴다는 의미인가? A. 이것도 아니다. P쪽에 control을 준다.
  - V(s): 1을 증가시킨다. 이때 p에 의해 막힌(block) s를 기다리는 스레드가 있다면 V는 그걸 재실행해준다. 이 P는 s를 한 번 감소시키고(decrement) 끝난다.
